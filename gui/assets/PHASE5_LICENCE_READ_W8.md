# PHASE5 LICENCE READ — Wave 8 Build 3 (Phase 5 picks)

Own code, standard library only. No third-party code, package,
model, font, sound pack, feed, or data is introduced by this
build, so no per-asset licence read is owed by this build itself.

Cluster by cluster:

- INTERFACES: descriptors only. No UI code, no font, no icon
  set, no copied HUD art is introduced. The Orbitron display-font
  OFL sighting and the Aura orb licence sighting are OWED by
  Wave 8 Build 4 (feel), not by this build, and nothing in this
  build claims them, bundles them, or depends on them.
- ENT shelf: catalogue records only. No entertainment asset is
  bundled, played, generated, or distributed by this build. Every
  item's licence label is caller-supplied and gated in code:
  copyleft (GPL/AGPL/LGPL/MPL), non-commercial, no-derivatives,
  revenue-capped, and territory-restricted labels are refused,
  and an unknown label is refused rather than assumed. A future
  build that actually bundles or plays an asset needs that
  asset's own primary licence read before it builds — this shelf
  does not grant one.
- PORT: single-device record-set round-trip over caller-supplied
  records. No third-party format is used (plain JSON + SHA-256);
  the existing ZIP portability bundle (core/portability.py)
  is not modified by this build.
- PLAT-TOOLS: programme records only. No third-party tooling,
  lifecycle, rollout, or governance product is introduced.
- FIN-PLAN: planning and record-keeping over caller-supplied
  amounts. No account connection, no payment rail, no market
  data, and no advice engine is introduced; ruling 34 (the
  transaction surface) is untouched and still gated.

Vetoed feel (Charon, M4, earcon family, F6 signatures, Space
Grotesk pairing) is refused in code by the ENT shelf and is not
present anywhere in this build. No face, no fake data, no
Marvel asset or trademark, no ripped movie or game audio is
introduced.

Verdict: OWN CODE, STDLIB ONLY — no licence blocker in this
build itself. Any future asset, font, sound, or feed added on
top of these records needs its own primary read first.
